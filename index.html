The Problem & Our Differentiation

Why Not Just "AI Notes" or a Chatbot?

Generic summarizers and chatbots-over-PDFs produce free-floating text prone to silent hallucinations. Confidently wrong notes are worse than no notes when preparing for exams.

Generic AI Summarizers & PDF Chatbots

Standard RAG / Black-box Summarization

  • No Syllabus Spine: Generates free-floating summaries without auditing whether syllabus topics are covered.
  • Silent Hallucinations: Blends real content with believable fabricated claims, misleading students during revision.
  • Blind to Coverage Gaps: Fails to tell you when a syllabus topic has zero supporting documents uploaded by the professor.

Syllabus-to-Notes Agent Pipeline

Syllabus Tree Driven + Verifier Agent

  • 1. Coverage Auditing: Constructs a strict topic tree from the syllabus first. Identifies topics with zero prof doc support.
  • 2. Claim Verification: The Verifier agent cross-checks every single generated claim against source chunks and explicitly flags unbacked statements.
  • 3. Fixed Structured Notes: Generates uniform study sections: Definition → Intuition → Example/Case Study → 2 Likely Exam Questions.

Strands Agent Orchestration

The 5 Specialized Agents

Instead of a monolithic prompt, our pipeline divides study generation into 5 deterministic agent roles orchestrated on Bedrock.

1

1. Parser

Syllabus → JSON Tree

Parses unstructured prose syllabi into Unit → Topic → Subtopic nodes using strict Bedrock JSON schema.

2

2. Mapper

Topics → OpenSearch

Queries Titan vector embeddings to map relevant prof doc chunks to each topic node. Detects gaps.

3

3. Writer

Topic → Draft Note

Drafts uniform sections: Definition, Intuition, Case Study, and 2 Exam Questions per topic.

4

4. Verifier

Claim Audit Engine

Audits draft notes against source chunks. Flags any unbacked statement (`⚠️ not in material`).

5

5. Assembler

Vault & PDF Renderer

Builds Obsidian `.md` vault with Map of Content (MOC) & wikilinks, then compiles to Pandoc PDF.
